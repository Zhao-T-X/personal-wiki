# 用户体验真实性审计：7 条真实用户旅程

> 本文件是 P0 阶段的第一步产出（UX Audit），不改动任何代码/UI。
> 所有观察都基于当前前端 `frontend/src` 与后端 `app/intent.py` 的真实实现，
> 而非凭空设想。每条旅程从"用户想法"出发，记录到达终点时的真实摩擦。
>
> 三条架构红线在本阶段继续有效（UX 改动不得破坏）：
> 1. 禁止新增绕过 Operation 的写入口；
> 2. 禁止新增第二套 Current Knowledge 判断；
> 3. 禁止新增重复 Read Model。

---

## 0. 真实用户模型（禁止按技术功能划分）

| 代号 | 是谁 | 典型一句话 | 内心问题 |
|---|---|---|---|
| **用户 A** | 第一次使用 | "我刚看到一篇文章，想保存下来。" | 这东西怎么开始？ |
| **用户 B** | 已经有知识 | "之前我记录过的东西是什么？""最近有哪些变化？" | 我存的东西在哪、变了什么？ |
| **用户 C** | 需要解决问题 | "帮我回答这个问题。""这个答案不对，我想纠正。""帮我深入研究。" | 怎么问、怎么改、怎么深究？ |

> 禁止使用的分类（出现过即记为 UX 问题）：Agent User / Research User / Knowledge User / Graph User。

## Journey 01：第一次打开

**用户想法：** "我第一次打开这个产品，我要干什么？"

**实测首屏（`HomeView` + `OneBox.vue`）**
- 首屏中央是 **OneBox** 单入口，提示文案"把知识交给我""问点什么、记点什么、研究点什么"。
- 上方/侧方可达：拖拽导入、`X 项需要你的判断`、`最近知识变化`。
- OneBox 自身**未暴露任何内部概念**（合规范例）。
- 侧栏导航含：知识 / 问答 / 研究 / 审核 / 纠正 / 设置，外加 Developer Mode 才出现的 智能体 / 评测 / 抽取实验。

**观察记录**

| 维度 | 记录 |
|---|---|
| 首屏看到什么 | OneBox 输入框 + 导入入口 + 最近变化/待判断摘要 |
| 第一注意力 | OneBox（居中、最强视觉权重）✅ |
| 是否理解产品价值 | 部分：文案只说"交给我/问/记/研究"，但没说"交了之后能得到什么" |
| 是否知道下一步 | 较清楚：要么输入一句话，要么拖文章 |
| 点击 / 输入次数 | 0 点击即可开始输入；导入需 1 次拖拽 |
| 是否出现陌生概念 | 首屏几乎无 ✅（最大亮点） |

**结论（P1）：** 首屏方向正确，但缺少一句"价值锚点"——用户不知道"交一篇
文章后会变成什么"。建议首屏补一条轻量示例链路（如"拖入一篇 → 自动整理成可问答的知识"）。

## Journey 02：第一次导入知识

**用户想法：** "我正在看一篇文章，想交给 Wiki。"

**实测路径（`ImportPanel.vue` → 处理 → `KnowledgeView`）**
- `ImportPanel` 用中文"切分片段 / 抽取知识 / 断言 / 实体 / 关系"，**未暴露 Chunk/Claim 等内部词**（合规）。
- 处理阶段文案"我从这篇整理出了什么"，方向正确。
- 处理完成后跳到 `KnowledgeView` 查看结果——**此处出现裸 `chunk #n`、
  `X chunks`、`Chunks`、`Embeddings` 按钮**（见概念矩阵）。

**重点观察：用户是否理解"系统正在做什么 / 提取出了什么 / 哪些已成为知识 / 哪些待确认"**

| 关注点 | 现状 | 判定 |
|---|---|---|
| 系统正在做什么 | "整理为知识…" 中文提示 | ✅ |
| 提取出了什么 | 结果以"知识对象 / 断言"呈现 | ✅ |
| 哪些已成为知识 | 已落库，可在知识页搜到 | ✅ |
| 哪些还需确认 | Review 页"X 项需要判断" | ⚠ 需主动去 Review，导入页未就地提示 |
| 下一步该干什么 | 弱：导入完无明确引导到问答/审核 | P1 |

**结论（P1）：** 导入主线可用且概念干净；断点在"导入完成 → 下一步"的引导缺失，
以及结果页把 `chunk`/`Embeddings` 暴露给用户。

---

## Journey 03：第一次提问

**用户想法：** "我想知道我以前保存过的东西。"

**实测路径（`QaView.vue`）**
- 当前 QA 同时存在 **知识库问答 / Agent 问答** 两种模式，并展示"自动路由 Agent""打开 Agent 工作台"。
- 后端 `intent.py` 把问句统一路由到 `/api/ask`（单一 ASK 意图），但**前端在 QA 页把
  "Agent" 作为显式可选模式暴露给用户**。

**验收红线（来自指令）：** 不允许要求用户理解 Knowledge QA / Agent QA 的区别。

| 维度 | 记录 |
|---|---|
| 用户是否需要懂 Knowledge/Agent 区别 | **需要**（前端提供切换 + 文案），违反红线 ❌ |
| 输入问题 → 获得答案 | 可达 ✅ |
| 看到依据 | 有引用/证据展示 ✅ |
| 继续追问 | 可达 ✅ |

**结论（P0）：** "用户是否必须理解 Knowledge/Agent 区别" 当前答案为 **是**，
正是指令点名的审查重点。这是本阶段最高优先级问题之一：要么在默认路径隐藏
Agent 模式（仅高级/开发者可见），要么把两种模式合并为单一"问"体验，内部自动路由。

---

## Journey 04：第一次纠正

**用户想法：** "这个答案明显不对，我要改。"

**实测路径（QA 页"这条有问题" → `CorrectionView` + `CorrectionFlow`）**
- 后端：`intent.py` 对含"不对/错了/纠正/应该是"等表述 → `correct` 意图 →
  `/api/knowledge/corrections`，且 `needs_confirmation=True`（先预览计划再执行），方向正确。
- 纠正流：自然语言 → 分析 → 新断言 + 演化关系预览 → 确认 → 成功 → 可再问。
- **但 `CorrectionView` 把 `CORRECT 操作` / `操作 ID：operation_id` 直接展示给用户**
  （Layer C 概念 Operation 泄漏，见概念矩阵）。

**必须检查项**

| 检查项 | 现状 | 判定 |
|---|---|---|
| 是否知道怎么改 | "这条有问题"按钮 + 自然语言输入 | ✅ |
| 是否理解旧知识发生了什么 | 演化关系预览（新断言/旧断言） | ✅ |
| 是否知道新知识已生效 | 成功提示 + 可再问验证 | ✅ |
| 是否能看到历史 | 纠正审计区（但含 raw `operation_id`） | ⚠ 审计有价值，但暴露 Operation 术语 |

**结论（P1）：** 纠正主线体验好；断点是审计区把 `operation_id`/`CORRECT 操作`
这种开发期概念暴露给普通用户，应改为"这条知识的修改记录"人话化。

## Journey 05：第一次研究

**用户想法：** "帮我深入研究一下。"

**实测路径（`ResearchView.vue`，经 OneBox "研究" 意图 → `/api/research`）**
- 后端对"研究/调研/分析一下/有什么变化/梳理"等 → `research` 意图，方向正确。
- **`ResearchView` 重度暴露内部概念**：`Total Claims` / `Candidate Claims` /
  `已保留 X 条 Claim` / `没有直接相关的 Claims` / `Claims 极性一致`，以及裸
  `predicate`、角色标签 `KnowledgeAgent` / `ResearchAgent`。

**验收红线（来自指令）：** 用户是否需要先理解 Research Task？是否自己选 Agent？
是否自己决定 Research / Knowledge？

| 问题 | 当前答案 | 判定 |
|---|---|---|
| 需要理解 Research Task？ | 页面以"Question→Evidence→Claims→Review→Knowledge 闭环"组织，用户被要求理解这套结构 | ❌ |
| 需要自己选 Agent？ | 页面展示 KnowledgeAgent/ResearchAgent 角色标签 | ❌ |
| 需要决定 Research/Knowledge？ | 不需要（OneBox 已路由），但进入后概念过载 | ⚠ |

**结论（P0）：** 研究页把"声明/谓词/Agent"当作界面主语，用户必须先学一套
内部词汇才能用。与"用户只需表达想做什么"的目标直接冲突。需把 Claim/Predicate/Agent
下沉为折叠/开发者可见，把页面主语改为用户语言（如"待你确认的研究发现 / 冲突 / 健康度"）。

---

## Journey 06：第二次回来（本阶段最重要）

**用户想法（隔一段时间后）：** "我为什么还要使用这个东西？"

**实测路径（`HomeView` 最近变化/待判断 → OneBox 自然语言）**
- 首页确实提供 `最近知识变化` 与 `X 项需要你的判断`——**方向正确，是留存触发器的雏形**。
- **但当用户用最自然的话问"最近我记录了什么"时，OneBox 返回 `unknown`，无任何路由。**

**实测证据（`app/intent.py` 真实输出）**

| 输入 | 路由结果 | 说明 |
|---|---|---|
| "帮我记住这个" | `knowledge` ✅ | 命中"记住" |
| "这篇文章讲了什么" | **`unknown`** ❌ | 词表只有"是什么/什么是"，缺裸"什么" |
| "苹果现在的 CEO 是谁" | `ask` ✅ | 命中"是谁" |
| "这个答案不对" | `correct` ✅ | 命中"不对" |
| "帮我研究这个问题" | `research` ✅ | 命中"研究" |
| **"最近我记录了什么"** | **`unknown`** ❌ | 裸"什么"未命中 → 无路由 |
| "我记录了哪些" | `ask` ✅ | 命中"哪些" |
| "最近有什么变化" | `research` ✅ | 命中"有什么变化" |

**必须观察项**

| 观察项 | 现状 | 判定 |
|---|---|---|
| 首页是否告诉我最近知识发生了什么 | 有"最近知识变化" | ✅ |
| 能否快速找到最近处理的内容 | 需进 Knowledge/Review 翻找 | ⚠ |
| 能否继续上次未完成任务 | 弱（无"进行中"入口） | P1 |
| 能否发现知识变化 / 冲突 / 待确认 | 有摘要，但需主动点入 | ⚠ |
| 能否马上提问 | 能（OneBox） | ✅ |
| **自然回访问句能否被理解** | **"最近我记录了什么"→unknown** | **P0** |

**结论（P0）：** 回访留存的核心触发器——"我之前弄了啥 / 最近变了啥"——在 OneBox
里**直接失效**。这是第五题"用户为什么还愿意回来"答不出来的最直接风险点。修复成本低
（扩展 `_QUESTION_MARKS` 加入裸 `什么`/`谁` 等），但必须先作为 P0 记入 Backlog，且
修复时**只能扩展意图词表、不能新增写路径**（守住架构红线）。

## Journey 07：知识规模变大以后（10 / 100 / 1000）

**假设规模**：10 篇文档 / 100 篇 / 1000 条知识。

| 页面 | 小规模 | 中规模 | 大规模风险 |
|---|---|---|---|
| `KnowledgeView` | 可用 | 搜索仍可 | 列表/图谱易失控；仍暴露 `chunk`/`Embeddings` |
| `ResearchView` | 尚可 | Claim 列表变长 | **`Total Claims` 等以内部实体为主语，越大越劝退** |
| `ReviewView` | 轻 | 待审堆积 | 需按"类别"分组已做，但标题含"Claims" |
| `ObjectView` | 单对象清晰 | — | 编辑弹窗暴露"Ontology 注册表约束" |

**结构性风险（P1→P0 随规模升级）：** 当知识变多，凡是以 `Claim`/`Predicate`/
`Chunk` 为主语的页面都会让用户"看到一堆自己不懂的零件"。应在规模上升前，把所有
Layer C 概念下沉为折叠/开发者可见，把列表主语换成"事实 / 来源 / 待确认"。

---

## 一页总结（给下一步"改"阶段用）

| Journey | 是否达成用户目标 | 关键断点 | 严重度 |
|---|---|---|---|
| 01 第一次打开 | 基本达成 | 缺价值锚点 | P1 |
| 02 第一次导入 | 达成 | 完成→下一步引导弱；结果页露 chunk/embeddings | P1 |
| 03 第一次提问 | **未达成** | 被迫理解 Knowledge/Agent 区别 | **P0** |
| 04 第一次纠正 | 达成 | 审计区露 operation_id | P1 |
| 05 第一次研究 | **未达成** | 被迫理解 Claim/Predicate/Agent | **P0** |
| 06 第二次回来 | **未达成** | "最近我记录了什么"→unknown，无留存触发器 | **P0** |
| 07 规模变大 | 待验证 | 内部概念主语随规模放大劝退 | P1（规模升级为 P0） |

> 阶段验收五问当前答案：Q1 知道下一步（✅ 大致）；Q2 导入看到"被理解"（✅）；
> Q3 提问需懂内部概念（❌）；Q4 像改一句话一样改知识（✅）；Q5 为什么回来（❌ 关键句失效）。
> Q3/Q5 不通过，故本阶段尚未形成使用闭环，先不堆功能。
